# Решения

1. **Пакет зависимостей.** Backend: FastAPI 0.141, SQLAlchemy 2.0.52 + aiosqlite, Alembic 1.20, Pydantic 2.13, argon2-cffi 25, fsrs 6.3.2, Pillow 12. Версии зафиксированы в `backend/requirements.lock` (pip freeze). Frontend: React 18, Vite 5, Tailwind CSS 4, TanStack Query 5, React Router 6, lucide-react.
2. **React Hook Form + Zod не подключены** — формы управляемые (controlled) с валидацией на схемах API и собственными хелперами; это осознанное упрощение (форм в ядре немного, сложная форма редактора — кастомная таблица, RHF там не помогает). Список «разумного набора» допускает выбор.
3. **dnd-kit не подключён** — сортировка карточек реализована нативным HTML5 drag-and-drop (desktop) плюс доступные альтернативы без DnD: кнопки вверх/вниз и ввод номера позиции. Это соответствует требованию «drag-and-drop и доступная альтернатива».
4. **Графики** — собственные маленькие SVG-компоненты (bar/line), а не библиотека: статистике нужны 2–3 простых вида.
5. **i18n** — собственный модуль (`src/i18n`): словари ru/en, функция `t(key, params)` с правилами русской плюрализации; fallback на русский + лог отсутствующего ключа в dev.
6. **Поиск** — SQLite FTS5 (unicode61) с таблицей `search_index`, синхронизируемой в транзакциях изменения карточек/наборов; при отсутствии FTS5 — автоматический fallback на LIKE по нормализованным колонкам. Проверено: в окружении FTS5 доступен.
7. **Часовой пояс по умолчанию** — `Europe/Moscow` (UI по умолчанию ru), меняется в настройках; валидация через `zoneinfo`.
8. **ID** — UUID-строки во всех таблицах (не перебираемые, стабильные для переносов и ссылок).
9. **Rate limit** — in-memory скользящее окно в процессе (один worker — допустимо); ключи: IP+username для login, IP для redeem/upload/import.
10. **Черновики теста** хранятся на строке `study_session_items` (`draft_answer`, `draft_version`) — собственная версия, устаревший PUT отклоняется.
11. **Learn-очередь** — состояние алгоритма в `study_sessions.state` (JSON), задания создаются сервером на каждом шаге (`item_id` выдаётся при показе), ответы идемпотентны по `client_event_id`.
12. **SRS-занятие** — очередь и оценки идут через `/srs/*` (обзоры, reviews, undo); запись в `study_sessions` (mode=srs) создаётся для статистики, планировщик вызывается только через `services/srs_service` (endpoint `/srs/reviews`).
13. **Активное время** — клиент шлёт heartbeat с дельтой активных секунд (page visibility + idle-детект на клиенте), сервер ограничивает дельту; метрика помечена как оценка.
14. **CSP** — без внешних источников; в dev Vite требует `unsafe-inline`/`ws` для HMR, в production — строгие заголовки.
