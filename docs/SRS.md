# SRS (интервальное повторение)

## Библиотека

Расписание считает [py-fsrs 6.x](https://github.com/open-spaced-repetition/py-fsrs)
через единственный адаптер `backend/app/srs/adapter.py`. Параметры приложения
не переизобретают формулы FSRS. Fuzzing отключён по умолчанию, чтобы
предпросмотр интервалов совпадал с принятым решением.

## Единица памяти

`(user_id, card_id, direction)`. Прямое (`front_to_back`) и обратное
(`back_to_front`) направления — независимые состояния; `both` — только настройка
выбора, отдельного состояния не существует. Перестановка сторон набора
обменивает направления у всех пользователей и увеличивает `version` состояний.

## Включение повторения

Создание набора не включает карточки в очередь автоматически. Пользователь
явно нажимает «Включить повторение» (набор → направление). По умолчанию
включается прямое направление; история направлений сохраняется при отключении.

## Оценки

«Не помню» (again) · «Трудно» (hard — вспомнили с затруднением) · «Помню»
(good) · «Легко» (easy). Забытая карточка оценивается «Не помню».

## Очередь

1. Просроченные и наступившие повторения (по `due_at`).
2. Новые единицы — в пределах дневного лимита (по умолчанию 20, считается по
   локальной дате пользователя при первом **принятом** review).

Обычные режимы (Cards, Learn, Write, Spell, Test, Match) не меняют FSRS-состояния.

## Целостность

- Один канонический endpoint `POST /srs/reviews`; общий механизм ответов занятий
  планировщик не вызывает.
- Review принимается одной транзакцией: событие + состояние + журнал.
- Идемпотентность: `client_event_id` уникален, повтор возвращает сохранённый
  результат; тот же ID с другим содержимым — конфликт.
- Конкурентная вкладка: conditional update по `version` состояния → 409.
- Устаревшая карточка: несовпадение `content_version` → 409 с предложением
  обновить вопрос.

## Хранение

`srs_states` хранит полный сериализуемый payload библиотеки (scheduler + card)
плюс денормализованные `due_at`, `last_review_at`, `state_name`, `version`,
`learning_epoch`, `suspended`. `srs_reviews` — журнал до/после (payload, due,
version), оценки и события отмены. Только `due_at` недостаточно для
восстановления планировщика.

## Отмена и сброс

- «Отменить последнюю оценку» — только для последнего review единицы:
  восстанавливает прежний payload и due, увеличивает техническую `version`,
  пишет событие отмены; история не стирается.
- «Сбросить прогресс» — новая учебная эпоха (learning_epoch + 1), старая
  история остаётся в статистике; подтверждение показывает число единиц.

## Настройки

- Целевая вероятность воспоминания: 0.90 (диапазон 0.80–0.97).
- Лимит новых единиц: 20 в локальные сутки.
- Размер раунда: 20 (не скрывает остальные просроченные карточки).
